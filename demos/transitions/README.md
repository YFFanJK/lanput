# LANPUT · 影院到音乐厅转场研究

双击 `index.html` 查看总览，或分别双击三个 HTML。每个方案自身包含样式、脚本、品牌图像与矢量场景，可单独复制、离线打开；不需要 Node、开发服务器或联网加载字体。

| 方案 | 文件 | 时长 | 重点 |
| --- | --- | --- | --- |
| 幕间换场 | 01-curtain.html | 3.6 秒 | 约 1 秒合幕，中间停留并出现过场语，再以约 1.4 秒开幕。最贴合刚确认的仪式感，优先推荐。 |
| 银幕入盘 | 02-screen-to-vinyl.html | 3.0 秒 | 银幕画面向唱片所在位置收拢，衔接成圆形黑胶，随后出现歌词。独立移动的画面与圆盘保持各自比例。 |
| 灯暗声起 | 03-lights-down.html | 2.8 秒 | 影院暗下，出现简短过场语，随后黑胶和歌词淡入。日常切换最轻，也最容易映射到现有 WPF。 |

三个方案使用相同的源场景、目标音乐厅、深蓝与暖金品牌、原创示例歌曲信息与歌词，便于比较转场本身。场景用 HTML/CSS/SVG 重现，不是截取或嵌入真实视频；唱臂固定，黑胶与中心标签一起旋转。

## 操作

- 正常动画设置下，打开约 2.2 秒后自动进入一次音乐厅，不循环抢走注意力。
- “模拟收到音乐”：从当前进度进入；已到音乐厅时重新演示。
- “返回影院”：支持反向转场；播放中可立即改变方向。
- “重播”：从影院重新演示。
- “转场进度”：手动查看中间帧。
- Esc：立即完成当前方向的切换；空格（焦点不在按钮、输入框时）：切换场景。
- 音乐厅内播放按钮：暂停／恢复模拟的唱片旋转。
- “减弱动态效果”：立即完成切换，停用旋转；同时尊重系统 `prefers-reduced-motion`。
- 页面进入后台时结束过场，避免回来后卡在半幕状态。

此处没有真实音频、手机连接、网络歌词或实际音量控制；播放器外围作为视觉参考，演示操作放在界面外部。

## 选定后接入原生软件的约束

本次仅新增 `demos/transitions` 和对应预览检查文件，未改动生产代码、安装包或软件配置。

后续应由已识别的媒体类型自动触发；同为音乐时切歌、暂停和缓冲不应反复换场。新请求、停止、关闭和关闭动画应能取消过场，按最新的媒体状态落到正确场景。音频播放与歌词时钟继续运行，转场结束显示当时的歌词，不从动画前的时间开始。

幕布方案可复用开幕动画材质；银幕入盘方案只能移动缓存画面或矢量海报，不移动、缩放真实视频 HWND。灯暗方案主要使用原生覆盖层透明度。三个方案均避免逐帧调整播放器尺寸。

## 验证

`check_demos.py` 用本机 Chrome / Playwright 检查三个离线文件：自动进入、唱片暂停、快速反向、Esc 清理、手动拖动、减少动态效果、系统减少动态效果、900 像素及 390 像素窗口、无横向溢出、无 JavaScript 错误。

截图与结果：`tests-output/transition-demos/`；日志：`tests-output/transition-demos-check.log`。

设计参考本次调用的 UI UX Pro Max 中关于连续性、可取消转场、变换与透明度性能、减少动态效果的适用建议。没有重新生成或覆盖全局品牌设计系统。
