# LANPUT 0.6.0 · 播放与连接体验更新

本版实施已确认的四项功能，并补上兼容渲染设置记忆；延续 0.5.0 的琥珀金界面和原生动画。

## 1. 真实播放阶段

播放器单独维护界面状态，UPnP 仍使用原有标准传输状态。界面区分：正在连接媒体来源、正在缓冲、等待视频画面、正在播放、已暂停和播放失败。

缓冲百分比只取自 LibVLC Buffering 事件的 Cache；没有数据时只显示“正在缓冲”，无效数值不显示。该数值代表引擎当前缓冲阶段，不是整部影片的下载进度。

中途缓冲且已有视频输出时，保留当前画面并显示轻量提示，不返回全屏等待页。暂停和停止优先于迟到的缓冲事件。全屏控制条在缓冲阶段保持可用。

## 2. 快捷播放

| 操作 | 行为 |
|---|---|
| 双击画面 | 切换全屏；双击按钮、滑块等控件不触发 |
| 左 / 右 | 后退 / 快进 10 秒；不越过影片起止边界 |
| 上 / 下 | 上增加 / 下减少 5%，范围 0–100% |
| M 或音量图标按钮 | 静音 / 取消静音 |
| 空格 | 播放 / 暂停 |
| F / F11 | 切换全屏 |
| Esc | 关闭弹窗或退出全屏 |
| Ctrl+O | 打开本地视频 |

左右键仅在媒体可定位且时长已知时有效；直播或不可定位媒体显示提示。输入框、网卡列表、进度/音量滑块和按钮拥有自身键盘操作；新快捷键不抢占这些控件，也不在设置/诊断弹窗中调整影片。

## 3. 启动后自动接收

设置新增“启动 LANPUT 后自动开始接收”，默认关闭。先手动成功接收一次，保存设备名称及网卡后，再开启此选项。

下次启动只选择保存的网卡。原网卡暂未出现时等待恢复；同一网卡仅有一个新 IPv4 地址时可适应 DHCP 变化；有多个候选地址且无法确定时不猜测。可以停止等待，手动另选网卡。

此选项不创建 Windows 开机启动项，也不自动更改防火墙规则。首次配置缺少已保存网卡时给出提示，不自动选中其他网络开始监听。

## 4. 连接检查

开始接收前自动检查，也可在接收设置中点击“连接检查”。简要结果在设置中显示，详细结果写入已有诊断记录。

- 检查所选网卡/地址是否仍存在、网卡是否已连接、是否为私人 IPv4、是否支持组播。
- 根据网卡名称、描述、类型提示疑似 VPN/虚拟网卡；这是启发式提醒，不强制阻止。
- 检查所选地址 TCP 41000 的已知监听冲突；IPv6-any 是否占用 IPv4 无法单凭监听列表确定时，仅作提醒。
- 已有本机接收服务运行时，不将其自身端口判成冲突。
- 缺少默认网关只提醒；隔离局域网仍可工作，不要求互联网。
- UDP 1900 可共享，因此不使用独占端口测试误判 SSDP；真正绑定与入组仍以接收服务启动结果为准。
- 检查不扫描手机、不修改网络配置，也不能证明防火墙已放行或手机一定能发现设备。路由器 AP 隔离/访客网络仍需人工核对。

## 5. 配置与服务收尾

兼容渲染选择写入 desktop.json，下次启动直接按该选项创建播放器。旧配置缺少 AutoReceive/CompatibilityRendering 时默认关闭，缺少 InterfaceAnimations 时仍默认开启。

接收服务已有启动失败清理；本版补充重复释放保护，并确保 SSDP 清理异常时仍关闭 TCP 服务。设置保存失败与服务启动失败分别处理，避免已经运行的接收服务被标为启动失败。

HTTP 客户端兼容标识、HLS 请求头、签名链接保留规则、SSDP 宣告格式及 UPnP SOAP 路由继续保留。
