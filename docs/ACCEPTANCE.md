# 实机验收记录

目标手机：Mate 80 Pro Max / HarmonyOS 7.0 / 华为视频 1.2.50。
目标电脑：MateBook GT 14 / Windows 11 x64。

## 开始前

1. 手机与电脑连接同一路由器的主网络，不用访客网络。
2. 在可信的家庭网络下，将 Windows 网络配置为“专用”。不需要关闭整个防火墙。
3. 先断开 VPN、代理或虚拟网卡的干扰（如会影响内网路由），接收器里选择实际局域网 IP。
4. 启动接收器，出现“接收中”；必要时在发布目录右键管理员运行 firewall.cmd。
5. 电脑浏览器打开 http://本机所选IP:41000/description.xml；手机浏览器打开同一地址，确认能看到 XML。
6. 再进入华为视频 TV 设备列表。浏览器能访问只证明 TCP 可达，不代表 SSDP 组播已经畅通。

## 失败分类

- **没有“收到设备搜索”**：确认网卡、组播、防火墙、AP 隔离、手机是否在这个入口使用 DLNA。不能直接归因于视频版权。
- **有搜索但不取设备描述**：可能过滤了设备信息/能力，或回应未到达手机，需要进一步分析。
- **已取描述但没有 SetAVTransportURI**：可能是协议匹配、应用策略或设备限制；保留手机提示。
- **收到地址但没有 Play**：记录控制顺序，不能自行把收到地址等同于播放指令。
- **收到 Play 后播放失败**：可能是失效地址、网络、编解码、额外请求头或 DRM；普通播放器错误无法唯一判定。
- **普通片源能播、目标会员片源失败且提示华为智慧屏/版权限制**：当前通用接收方案没有满足该片源的授权/设备要求。

“目标会员影片正常播放”才是本项目主要验收条件。发现设备、播放本地视频或免费影片不能替代。

HTTP 检测是独立请求，不使用账号 Cookie，不自动跟随重定向，仅额外读取最多 1KB。HTTP 200 不保证分片、解码或授权成功；检测的 401/403 也不能代替引擎实际错误。

兼容模式为软件解码 / Direct3D 9；切换会清空当前媒体，需要重新打开或重新投屏。此路径同样待目标电脑实测。


## 0.2.1 HTTP 403 与退出复测

1. 关闭旧版，构建新版，重新从手机选择影片投放；不只按电脑“播放”重试旧链接。
2. 若仍失败，确认状态是否保持 ERROR_OCCURRED；点击“检测当前媒体”，等待 A/B 对照完成后复制诊断。
3. 入口检测成功不代表后续分片、密钥或授权成功；入口两种请求均被拒绝也不直接等于 DRM。
4. 明确“退出”表现：手机结束投屏，还是电脑整个程序窗口消失。若整个窗口消失，保留日志目录 `application-*.log`，不要反复清空日志。
5. 应用日志并不能保证捕获原生崩溃或进程被外部终止；没有正常退出记录只是线索，不是唯一诊断依据。


## 0.2.2 剪贴板异常回归

- 点击“复制诊断”：检查摘要已复制，且日志目录出现 diagnostic-summary-*.txt。
- 剪贴板暂不可用时：最多尝试 3 次，显示失败提示但程序继续运行；文件后备存在。
- 点击“导出诊断”：选择保存位置并打开文本，整个操作不依赖剪贴板。
- 复制重试期间关闭窗口，不出现第二次未处理异常。
- 媒体 403 仍需点击“检测当前媒体”，等入口 A/B 结果生成后，导出完整诊断。


## 0.2.3 HLS 复测

1. 关闭旧版并构建新版，从手机重新选择片源并投放，避免只重试旧链接。
2. 若新客户端标识下仍失败，点击“检测当前媒体”，等 HLS 阶段结束（最多 40 秒，入口检测另计）再导出。
3. 保留每一条 `HLS 链路` 和 `HLS 列表信息`。入口/子列表/密钥/分片的错误不能互相替代。
4. 入口同客户端标识返回 403 而旧普通请求 206：仍需区分请求标识、Range、重定向等条件，不把它认定为分片问题。
5. 入口/子列表成功而密钥失败：优先检查对应密钥请求授权或协议要求；不能仅凭 403 认定 DRM 类型。
6. 全部抽样成功而播放仍失败：不能推出所有资源都正常，继续检查实际选择的码率、其他分片、请求差异及解码。

日志不输出原始 URL、查询参数、播放列表正文或密钥字节，不需要提交账号密码或 Cookie。
