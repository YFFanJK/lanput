# LANPUT 0.9.4 · 原生幕间换场

将用户选定的 `demos/transitions/01-curtain.html` 融入原生 WPF。识别到纯音频后，影院合幕，出现“这一场，听音乐 / 私人音乐厅”，再打开黑胶音乐厅；停止、结束或改为视频时向影院方向换场。

## 节奏

总长 3.6 秒，保持 HTML 方案的分段平滑曲线：前 27% 合幕，44% 时在完全闭合的幕布后切换场景和共享控制栏，60% 后开幕。过场文字在中间的闭幕区间淡入、停留、淡出。

窗帘复用深蓝开幕材质。只动画化位移与文字透明度；控制栏只在闭幕时调整一次布局，不逐帧缩放真实视频或重建播放器。

控制栏调整会改变银幕可视区域高度，过场文字单独保持原来的物理中心位置，避免闭幕期间出现上下跳动。原生回归同时检查文字在布局切换前后的坐标。

## 播放与中断

- 音频和歌词时钟照常运行；开幕后显示当前播放位置的歌词，不从旧时间重新播放。
- 识别中的新歌曲保留音乐厅；同为音频的换源、暂停、恢复、缓冲不重复换场。已知视频轨道或实际视频输出可触发退出音乐厅。
- 处理 SetAVTransportURI 在 Play 前的短暂 STOPPED 状态，避免每次切歌先回影院。
- 曲目停止时，唱片先停在原角度，待幕布遮住后才清理旋转状态。
- 再次改变媒体类型、停止、Esc、跳过按钮、点击、窗口宽度改变、全屏、最小化、隐藏、关闭或关闭动画时，可立即结束旧过场并落到最新场景。
- 每次动画带有序号检查，旧完成回调不能覆盖新媒体状态。
- 软件或系统关闭动画时立即切换，不保留遮罩；从托盘恢复不会补播过场。
- 原生开场与换场不会叠加；新媒体请求会让开场退场。

视觉状态与音频识别状态分离，歌词查询、取消与媒体版本守卫继续沿用现有流程。没有更换原生音乐厅和影院设计。

## 验证

`tests-output/MusicTransitionHarness` 使用真实 LibVLC 本地测试媒体，覆盖自动进入、闭幕区间和控制栏切换、音频持续推进、歌词跟随当前时间、曲目替换、暂停恢复、停止返回、Esc、停止后旧回调不回弹、新视频接管、关闭动画、调整大小、全屏与动画期间退出。日志：`tests-output/music-transition-check.log`。

`tests-output/NativeMusicHarness` 回归唱片旋转、窗口最小尺寸／普通／最大化／全屏布局、专辑信息边界、鼠标进度点击与拖动、歌词定位及音视频切换。日志：`tests-output/music-transition-player-regression.log`。

本次未重新进行所有手机播放器的真机互通测试。协议与歌词回归仍由正式打包脚本执行。

## 交付

- 安装包：`dist/LANPUT-0.9.4-Setup-x64.exe`。
- 便携包：`dist/LANPUT-0.9.4-win-x64.zip`，解压后保留完整目录。
- 项目根目录 `run.cmd` 直接启动本次更新后的 `dist/LANPUT-win-x64/LANPUT.exe`。

在线发布服务未由本次本地打包修改。需要发布时，将真实安装包上传后交给服务器助手执行：

```bash
lanput-publish.sh 0.9.4 /root/LANPUT-0.9.4-Setup-x64.exe "影院与音乐厅新增自动幕间换场，保留连续播放和歌词计时，切歌暂停不重复换场，可随时跳过。"
```
