# LANPUT 0.7.1 · 欢迎画面过渡

0.7.1 替换了 0.7.0 逐帧调整原生视频窗口尺寸的做法。

真实 VideoView 始终占满播放区域。观众席、银幕海报和欢迎语统一绘制在不透明的 WPF 视频叠层中；银幕源画面尺寸固定，动画仅改变缓存画面的 RenderTransform 与透明度，文字不随动画反复重排。用户实际调整窗口尺寸时才更新画布尺寸。

开映流程：视频输出就绪 → 显示“好戏马上上演” → 约 1.6 秒欢迎画面推进 → 约 180 毫秒淡出遮罩 → 展示完整影片。推进过程中不显示真实投屏画面，也不逐帧调整 VideoView/HWND 的尺寸。

支持暂停的片源在欢迎期间暂缓播放；结束后继续。用户在欢迎期间发出的暂停会保留，停止和换片会取消旧的过渡回调。非暂停型直播输入保持自身播放时钟，画面在欢迎完成后显示，不强行暂停直播。

停止或播放结束时先显示“欢迎再次入座”遮罩，再反向过渡到观众席。暂停、恢复和中途缓冲不会重复开场。关闭界面动画后直接切换并释放欢迎暂停。

仅在播放器明确允许欢迎期间暂停时，UPnP 才允许 TRANSITIONING 状态的 Pause；其他打开/停止状态仍保留原有校验。

验证：46 项核心回归测试通过；GUI + UPnP 实播检查覆盖原生窗口固定尺寸、欢迎期间播放进度保持、欢迎后的继续播放、暂停/恢复、欢迎期间显式暂停、软件按钮在欢迎期间继续、欢迎期间停止、防止旧回调恢复停止的影片、欢迎期间换片、自然结束、失败片源、全屏及禁用动画。实测使用本机 HTTP 测试影片，未对所有手机与片源逐一验证。
