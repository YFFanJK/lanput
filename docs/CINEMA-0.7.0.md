# LANPUT 0.7.0 · 自动影院

待机影厅包含观众席、过道灯、壁灯与中央银幕。银幕内使用用户选择的透明 LOGO，文案为：

> 手机选好影片，投屏，剩下的交给LANPUT。

| 播放状态 | 影院行为 |
| --- | --- |
| 待机、仅启动接收、媒体打开中且尚无视频输出 | 保留观众席和中央银幕 |
| 视频输出已建立并进入播放 | 约 1.9 秒自动推进到完整播放区域 |
| 暂停、恢复、已进入播放后的暂时缓冲或视频输出暂时丢失 | 保留完整银幕 |
| 收到停止、影片自然结束、播放失败 | 约 1.5 秒返回影厅 |
| 用户关闭界面动画、系统关闭客户端区域动画、窗口隐藏或最小化 | 直接应用目标布局，停止装饰动画 |

“完整银幕”指填满应用播放区域，遵循用户已有的窗口或 F/F11 全屏选择。不会主动改变 Windows 窗口全屏状态。全屏待机时，可使用影厅里的“返回窗口 · Esc”按钮。

原播放控制、播放信息、诊断和接收服务保留。待机通知位于操作按钮上方独立占位，播放中的通知继续使用视频叠层。暂停不退场，片源加载失败不会误触发开映。

影院使用冻结的原生 WPF 矢量图，不依赖 WebView 或网络资源；待机无持续场景渲染循环。真实视频通过布局调整 HWND 尺寸推进，避免对原生视频宿主直接做缩放变换。依据：[VideoLAN WPF VideoView](https://github.com/videolan/libvlcsharp/blob/3.x/src/LibVLCSharp.WPF/README.md)、[Microsoft WPF/Win32 互操作](https://learn.microsoft.com/dotnet/desktop/wpf/advanced/wpf-and-win32-interoperation)。

验证包含：45 项核心回归用例；实际 UPnP 请求触发的自动开映、原生视频窗口连续尺寸变化、暂停/恢复、停止、自然播完、进场中停止、404 失败、全屏进出影院、禁用动画与正常退出。实际 GUI 测试使用本机 HTTP 测试视频，不代表已实测所有手机与网络片源。
